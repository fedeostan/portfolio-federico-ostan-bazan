# Case studies — intake convention

Each real case study on the site lives as one folder under `content/case-studies/<slug>/`. This file documents the convention so Fede can onboard a new project in five minutes and Claude can process it end-to-end.

## Per-project layout

```
content/case-studies/<slug>/
├── brief.md          ← raw dictation dump (Fede authors)
├── meta.yaml         ← structured fields (Fede authors)
├── images/           ← real images (Fede drops)
│   ├── hero.png            → asset type="hero", 1600×900 target
│   ├── cover.png           → projects.og_image, 1200×630 target
│   ├── gallery-01.png      → asset type="screenshot", order=10
│   ├── gallery-02.png      → asset type="screenshot", order=20
│   └── process-01.png      → paired with image+text section, order=15
├── assets.json       ← generated by `pnpm assets:upload <slug>` (filename → public URL)
└── case-study.ts     ← generated by Claude (typed SeedProject default export)
```

`brief.md` and `meta.yaml` are the only files Fede authors by hand (plus the images). `case-study.ts` and `assets.json` are produced by the pipeline.

## `meta.yaml`

Hard-structured fields Claude can't reliably infer from the brief. Example:

```yaml
slug: aurora              # URL slug; must match folder name
title: Aurora             # display title
client: Northwind Bank    # real company name (set nda: true to anonymize)
role: Lead Product Designer
year: 2024
category: ai              # one of: ai | mobile | desktop | personal
published: true
tech_stack: [Figma, SwiftUI, Python]
nda: false                # if true, Claude anonymizes client → e.g. "a European neobank"
```

## `brief.md`

Free-form dictation dump. No structure required. Useful things to cover (Claude extracts whatever's in the dump):

- What the product is and who uses it
- The real problem you were solving
- Your role (designer, lead, IC, etc.) and the team you worked with
- The approach — research, experiments, key design decisions
- What shipped — features, scope, timeline
- The outcome — qualitative and quantitative (Claude will invent realistic metrics if you don't supply them)
- What was hard, what you learned
- Tools, collaborators, clients

Don't worry about structure or polish. The `direct-response-copy` skill and `WebSearch` validation will turn the dump into a real case study.

## Images

Drop files in `images/` with these conventional names. The **container aspect ratio** comes from the actual component CSS — match it or get awkward crops. Pixel sizes below are 2× retina targets.

| Filename pattern | Asset type | Where it renders | Container | 2× target |
|---|---|---|---|---|
| `hero.{png\|jpg\|webp}` | `hero` | `CaseStudyHero` — wide letterbox band at top of detail page | **2.5:1 ultra-wide** | **2280×914** |
| `cover.{png\|jpg\|webp}` | sets `projects.og_image` — drives the **home grid card** visual (not social/OG; that's dynamic via `app/case-studies/[slug]/opengraph-image.tsx`) | **0.79:1 portrait** (34:43 — same as process slots) | **680×860** |
| `process-NN.{ext}` | `screenshot` | `TextImageSplit` — paired with `image+text` sections by `order`. The section heading is **overlaid at the bottom of the image** | **0.79:1 portrait** (phone-mockup slot) | **680×860** |
| `gallery-NN.{ext}` | `screenshot` | `Gallery` block — full-width below text | **~1.58:1 landscape** | **2280×1440** |

**The portrait slot is intentional.** `TextImageSplit` (`components/case-study/TextImageSplit.tsx`) is designed for phone-frame mockups with the section title rendered inside the image at the bottom. For desktop/laptop screens, letterbox them inside a portrait frame, or move the asset to a `gallery` section instead.

**Metrics formatting matters.** `MetricsRow` renders headline-style — keep exactly **3 metrics**, each value ≤ 2 words / 12 characters (`"2"`, `"44%"`, `"D30 58%"`, `"Holdings-only"`). Sentences blow out the layout.

Supported extensions: `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.svg`, `.avif`, `.mp4`, `.webm`.

## The pipeline ("process `<slug>`")

When Fede says **"process `<slug>`"**, Claude:

1. Reads `brief.md` + `meta.yaml` + lists `images/`
2. Uses `direct-response-copy` + `WebSearch` to validate facts and inflate copy. Invents metrics realistically.
3. Writes `case-study.ts` exporting a typed `SeedProject` (sections + assets reference images by **filename**, not URL)
4. Runs `pnpm assets:upload <slug>` — uploads to Supabase Storage bucket `project-assets/<slug>/`, writes the public-URL map to `assets.json`
5. Runs `pnpm db:seed` — wipes-by-slug, loads every `content/case-studies/*/case-study.ts`, resolves filenames via `assets.json`, inserts
6. Verifies at `http://localhost:3000/case-studies/<slug>` and via the AI brief chat ("tell me about `<slug>`")

## Re-uploading images

```bash
pnpm assets:upload <slug>           # uploads new files, skips existing
pnpm assets:upload <slug> --force   # overwrites every file in Storage
pnpm assets:upload --all            # uploads all slugs (rare)
```

`assets.json` is committed to git so `pnpm db:seed` works on any fresh checkout without re-uploading.

## When a project is WIP

Put the folder in place (`brief.md`, `images/`, `meta.yaml`) without running `assets:upload` yet. `pnpm db:seed` will print `⚠ <slug>: no assets.json — skipping` and continue. No need to delete or gitignore WIP folders.

## Anatomy of a generated `case-study.ts`

```ts
import type { SeedProject } from "@/lib/case-study/seed";

const project: SeedProject = {
  slug: "aurora",
  title: "Aurora",
  client: "Northwind Bank",
  role: "Lead Product Designer",
  year: 2024,
  category: "ai",
  published: true,
  summary: "…",
  description: "…",
  tech_stack: ["Figma", "SwiftUI", "Python"],
  metrics: { adoption: "18% drop in onboarding drop-off", … },
  og_image_file: "cover.png",
  sections: [
    { section_type: "text", heading: "…", content_md: "…", order: 10 },
    { section_type: "image+text", heading: "…", content_md: "…", order: 20 },
    { section_type: "metrics", heading: "Outcomes", content_md: null, order: 30 },
    { section_type: "gallery", heading: "Screens", content_md: null, order: 40 },
  ],
  assets: [
    { type: "hero", file: "hero.png", alt_text: "…", caption: "…", order: 10 },
    { type: "screenshot", file: "gallery-01.png", alt_text: "…", caption: "…", order: 20 },
  ],
};

export default project;
```

Section `section_type` must be one of `text | image+text | metrics | gallery` (see `lib/case-study/sections.ts`). Section `order` and asset `order` use a `10, 20, 30…` cadence so inserts between existing items don't force renumbering.
